# 품질과 안전

[English](QUALITY-AND-SAFETY.md)

PCssak AroDamA는 한 줄을 복사하든 2만 자를 복사하든 지금 편하고 나중에 다시 찾을 수 있어야
하며, 불확실성을 사용자에게 숨기지 않는다는 원칙으로 설계합니다. 무료 Early Access는 완벽한
호환성을 주장하는 표현이 아닙니다.

## 현재 릴리스와 근거의 범위 — 2026-09-03

이 문서는 [v0.4.2](https://github.com/pcssakinc/pcssak-arodama-releases/releases/tag/v0.4.2)를
대상으로 합니다. 배포 준비 중 자동 검증, 공개 자산 확인, 실제 PC 검수를 구분합니다.
문서 갱신 자체가 공개 배포나 Windows 설치 성공의 근거는 아닙니다.

| 근거 | 확인 상태와 범위 |
| --- | --- |
| 0.4.2 Rust 자동 시험 | Windows x64 `335/335`, x86 `335/335` 통과 기록. 대상별 자동 시험이며 깨끗한 PC 설치 시험이 아닙니다. |
| 0.4.2 화면 동작 회귀 검사 | 복사·최초 동의 완료·입력 대상 분리·모음 이동 관련 `21`개 통과 기록. 격리·대역 시험은 실제 Windows 입력 동작의 증명이 아닙니다. |

| 접근성·원어민·법률·외부 보안 검토 | 정확한 배포본의 별도 근거가 없는 광범위한 인수 검수는 대기로 유지합니다. |

향후 결과에는 정확한 버전·파일 해시, 실행일, Windows 빌드·아키텍처, 시나리오, 기대·실제 결과와
자동 시험·실제 PC·미실행을 구분해 기록합니다. 합성 자료만 사용하고 개인 경로·원본 로그는
제외합니다. 확인된 오류는 수정·릴리스와 연결하며, 과거 결과를 소급해 바꾸지 않고 정정 내용을
별도로 남깁니다.

## 안전 원칙

1. **수집 전 동의:** 관련 설명을 제공하고 사용자가 명시적으로 동의하기 전까지 클립보드 수집과
   자동 업데이트 확인을 켜지 않습니다.
2. **로컬 우선·최소 수집:** 핵심 클립보드 내용은 사용자 PC에 두고 네트워크는 문서화한 업데이트와
   사용자 직접 실행 경로로 제한합니다.
3. **상한 있는 작업:** 수집 대기열·페이로드·미리보기·이미지 캐시·가상 파일 추출·검색 후보·
   페이지에 상한을 두어 손상되거나 극단적인 입력이 자원을 무한히 쓰지 않고 안전하게 실패하게
   합니다.
4. **정직한 결과:** 복사 성공, 붙여넣기 입력 전송, 다른 앱의 데이터 저장 증명은 서로 다른
   상태이며 근거 없이 마지막 상태를 성공으로 표시하지 않습니다.
5. **백엔드 정책 집행:** 보관·삭제·복구·민감 항목·업데이트 검증·백업 인증을 보이는 화면보다
   아래 계층에서도 강제합니다.
6. **복구 가능한 트랜잭션:** 스키마 이전과 백업 복원에 검증·원자 교체·롤백 경계를 두며, 실패 시
   가능한 한 마지막 정상 데이터를 보존합니다.
7. **재현 가능한 릴리스 근거:** 아키텍처·소스 커밋·빌드 영수증·자산 바이트·업데이트 서명·
   체크섬·SBOM·고지·상호주의 라이선스 대응소스를 독립 관문으로 검증합니다.

## 0.4.0에 기록된 자동 검증

준비된 `0.4.0` 코드와 배포 후보에는 다음 시점 증거가 기록되어 있습니다.

- Windows x64와 x86 대상 Rust 전체 시험이 각각 `316/316` 통과했습니다.
- 두 대상의 Clippy 경고 금지, rustfmt, 프런트 프로덕션 빌드, Tauri 무번들 디버그 빌드와
  업데이트 정책 시험이 통과했습니다.
- 앱 여덟 언어를 언어당 `474`개 키로 검사해 누락·추가·중복·빈 값·치환 변수 불일치를
  확인했습니다.
- EULA 생성, 법률 문서 지문, 제3자 고지, CycloneDX SBOM, MPL-2.0 대응소스 독립 재생성
  검증이 통과했습니다.
- 당시 npm 감사는 알려진 취약점 0건이었습니다. RustSec의 허용된 유지보수 중단·불건전성 경고를
  문서화했으며 선택된 Windows 대상 그래프에 영향을 주는 알려진 취약점은 확인되지 않았습니다.
- x64·x86 설치 후보와 앱 본체는 한 시점의 Microsoft Defender 사용자 지정 검사에서 탐지
  0건이었습니다.

이 결과는 시험한 정확한 바이트와 의존성 그래프에만 적용됩니다. 이후 소스·도구 체인·서명·패키징·
메타데이터·자산이 바뀌면 관련 시험과 해시를 다시 생성해야 합니다. Defender 결과는 SmartScreen
평판, 다른 백신 엔진이나 향후 정의를 보증하지 않습니다.

## 과거 0.4.0 공개 배포 관문

아래는 0.4.0 당시 관문을 보존한 기록입니다. 현재 버전과 파일명은
[릴리스 자산 정책](RELEASE-ASSET-POLICY.md)을 따르며 최신 버전이 바뀌었다고 과거 버전 고정
공식 배포가 무효가 되는 것은 아닙니다.

다음 항목이 모두 일치할 때만 게시할 수 있습니다.

- 승인된 소스·빌드·영수증·게시 커밋
- 최종 x64·x86 설치본 바이트와 아키텍처
- 설치본과 같은 이름의 Tauri 업데이트 서명
- 비밀이나 로컬 경로가 없는 `BUILD-PROVENANCE.json`
- CycloneDX SBOM 둘과 정확한 MPL-2.0 대응소스 압축 파일
- 현재 법률·개인정보·보안·지원·릴리스 노트·제3자 고지 바이트
- 최종 체크섬 파일 이외 16개 자산을 포함한 `SHA256SUMS.txt`
- 정확한 공개 설치본과 서명을 가리키는 `latest.json`
- 정확히 17개 자산을 가진 초안·Prerelease가 아닌 GitHub Latest `v0.4.0`
- 익명 재다운로드와 독립 해시·서명 검증

생성된 설치본·`.sig`·SBOM·MPL 소스 압축·출처·체크섬·`latest.json`은 Git 저장소 트리가
아니라 버전 고정 GitHub Release에만 둡니다.

## 자동화가 대신하지 못하는 근거

다음 항목은 정확한 공개 바이트에 대한 별도 결과를 기록하기 전까지 실제 환경 검수로 남습니다.

- 깨끗한 Windows 11 x64와 Windows 10 22H2 x64/x86 설치·업데이트·제거·재부팅·절전 복귀·
  다중 모니터·배율·저장공간 부족 시험
- 광범위한 Office·브라우저·Explorer·암호 관리자·OCR·IME·원격 세션·관리자 프로세스·접근성
  도구·백신·기업 정책 호환성
- 지원 배율·언어에서 키보드 전용·화면 읽기 도구·실제 화면 검수
- 여덟 언어 원어민 검수
- 관할별 법률 자문·상업 조건과 전문 접근성·보안 인증
- SmartScreen 평판과 장시간·대용량 사용자 인수 시험

결과가 기록되기 전에는 통과라고 하지 않고 `NOT_RUN`·제한·대기로 표시합니다. 사용자에게 보이는
경계는 [알려진 한계](KNOWN-LIMITATIONS.ko.md)를 확인하십시오.

## 품질 문제 신고

구조화된 버그 양식에 합성 데이터를 사용하십시오. 정확한 버전·Windows 빌드·아키텍처·데이터
종류·기대 결과·실제 결과와 데이터가 안전하게 남았는지 적습니다. 실제 클립보드 내용·DB·백업·
자격증명·고객 자료·개인 경로를 첨부하지 마십시오. 보안 영향이 있는 동작은
[SECURITY.md](../SECURITY.md)의 비공개 절차로 신고합니다.
